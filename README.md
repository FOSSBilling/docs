# FOSSBilling Docs

Source for [FOSSBilling documentation](https://docs.fossbilling.org), built with Astro, Starlight, and Markdoc.

## Local Development

Use Node.js 26.12 or later in the 26.x series to match CI.

```bash
npm ci
npm run dev
```

Open [localhost:4321](http://localhost:4321). Run `npm run format:check`, `npm run check`, and `npm run build` before opening a PR against `main`.

If GitHub requires approval to run CI on a fork PR, a maintainer can select **Approve and run workflows**.

## Editing Content

- Write `.mdoc` pages in `src/content/docs/` with `title` and `description` frontmatter. Name section overviews `index.mdoc`.
- Use title case for page titles, headings, sidebar labels, callout titles, and card titles. Capitalize the first and last words, major words, and phrasal verb particles. Lowercase articles, coordinating conjunctions, and prepositions of up to four letters in the middle of a title. Apply the same rules to hyphenated terms.
- Document the latest stable FOSSBilling release by default. Mention specific versions for release notes, migrations, or version-specific behavior. Pin source links when citing specific implementation details.
- Check the sidebar in [`astro.config.ts`](./astro.config.ts) when adding pages. In autogenerated sections, use `sidebar.label` or `sidebar.order` to override the label or position.
- Use root-relative internal links with trailing slashes. When moving a page, update its links and add a rule to `public/_redirects` if the old URL needs a [redirect](https://developers.cloudflare.com/workers/static-assets/redirects/).
- Put documentation images in `src/assets/` and reference them with relative paths. Get logos and browser icons from the [branding manifest](https://branding.fossbilling.org/manifest.json).

## Deployment

[CI](./.github/workflows/ci-cd.yml) builds the site with Astro and the Cloudflare Vite plugin. The shared Cloudflare workflow deploys the prebuilt output to production from `main` and to previews under `docs.fossbilling.foo` from other branches in this repository. Deployments require successful checks and a build from the current branch head. [Cloudflare Events](./.github/workflows/cloudflare-events.yml) posts preview links on PRs and cleans up branch previews on same-repository PR close or branch deletion. See [`cloudflare.config.ts`](./cloudflare.config.ts) for Worker settings.

After CI passes for a fork PR targeting `main`, a maintainer can approve its preview through **Review deployments** in the Cloudflare Events run. Open the preview from the GitHub deployment. Preview names of the form `pr-<number>` are reserved for fork PRs, and a daily job removes previews for closed PRs. If the build artifact expires after 14 days, rerun all jobs in the PR's CI/CD run and approve the new deployment.
